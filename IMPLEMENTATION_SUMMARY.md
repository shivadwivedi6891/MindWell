### 4. API Controller Endpoints
**Modified File:** [MentalHealth.API/Controllers/ChatSessionsController.cs](MentalHealth.API/Controllers/ChatSessionsController.cs)

#### New Endpoints:

1. **POST /api/chat/sessions/{sessionId}/pause**
   - Pauses a chat session
   - Response: `ChatControlResponseDto`
   - Only experts can pause OneToOne chats
   - Any participant can pause Peer chats

2. **POST /api/chat/sessions/{sessionId}/resume**
   - Resumes a paused session
   - Response: `ChatControlResponseDto`
   - Only experts can resume OneToOne chats
   - Any participant can resume Peer chats

3. **POST /api/chat/sessions/{sessionId}/end**
   - Ends a chat session permanently
   - Response: `ChatControlResponseDto`
   - Any participant can end a session

4. **GET /api/chat/sessions/{sessionId}/messages**
   - Retrieves paginated message history
   - Response: `List<ChatMessageDto>`
   - Query parameters: `page` (default: 1), `pageSize` (default: 50, max: 500)
   - Only participants can view history

## Business Rules Implemented

### Pause Chat
- Creates system message: "Chat paused by [role]"
- Sets `IsPaused = true`
- Broadcasts via SignalR to session group
- Only experts can pause OneToOne sessions
- Any participant can pause Peer sessions

### Resume Chat
- Creates system message: "Chat resumed by [role]"
- Sets `IsPaused = false`
- Broadcasts via SignalR to session group
- Only experts can resume OneToOne sessions
- Any participant can resume Peer sessions

### End Chat
- Creates system message: "Chat ended by [role]"
- Sets `IsActive = false`, `EndedAt = DateTime.UtcNow`
- Broadcasts via SignalR to session group
- Any participant can end a session

### Message History
- Paginated retrieval (newest first in DB, oldest first in response)
- Only participants can view
- Respects anonymity settings (IsIdentityRevealed flag)
- Excludes deleted messages (`IsDeleted = false`)

### SignalR Message Sending
- Prevents sending if `IsPaused == true`
- Prevents sending if `IsActive == false`
- Validates participant membership
- Persists messages with `CreatedAt` timestamp
- Broadcasts to session group

## Security & Validation

✅ **JWT Authentication** - All endpoints require `[Authorize]`
✅ **Participant Verification** - Only participants can access/modify sessions
✅ **Role-Based Access** - Pause/Resume differentiated by role and session type
✅ **Input Validation** - Pagination limits enforced (max 500 per page)
✅ **State Validation** - Cannot double-pause, double-resume, or end already ended sessions
✅ **Proper Error Responses**:
   - `404 Not Found` - Session doesn't exist
   - `403 Forbidden` - User not participant or lacks permission
   - `400 Bad Request` - Invalid state or parameters
   - `401 Unauthorized` - Missing JWT
